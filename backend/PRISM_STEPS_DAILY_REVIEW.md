## Companion release and operational boundary

Canonical project: `appgprj_6ad37e842c808191bbf2e1b58457e71c`.
New daily route: `POST /api/steps/daily` with exactly `{"action":"sync"}`.
No caller-supplied dates, source URLs, credentials or metrics. The owner-private
Sites edge authenticates a service call without visitor identity. The updater
binds the single owner evidenced by existing email-checked pilot connection,
snapshot and receipt rows; it also rejects conflicting Steps/HAE owners.
Absent/ambiguous evidence fails closed before fetching and is rechecked inside
the commit transaction. Present browser identity must match configured owner
email and bound ID; cross-origin mutations are rejected. Do not make this
Site public. A service credential conveys neither visitor identity nor app
consent and must be sent only to this same Site's platform header.

The separate daily switch defaults off, including after this compatible Site
publication. Opening the UI reads saved Site status only. Daily uses a separate
source URL/token and never changes `PRISM_STEPS_ENABLED` or the pilot URL/token.
At most three sequential, 16-KiB validated v1 responses are fetched. A 20-second
whole-run deadline and 60-second lease protect the run; transaction-time SQL
also checks the deadline/lease, nonce and unique owner. All date snapshots and
per-date/run receipts commit in one D1 batch. Failed runs leave the prior
complete set and successful-fetch timestamp intact, with sanitized status.
Unavailable stores null and retains per-day last-known evidence separately.
Local normalized content hashes, excluding credential state, detect corrections
even if a source fingerprint is reused; values are replaced, never summed.
[D1 batch transaction reference](https://developers.cloudflare.com/d1/worker-api/d1-database/).

Migration `0005` only adds daily tables and indexes. Existing pilot, HAE,
Hevy, history and notes/backups are unchanged. First complete daily run copies
the fixed-day pilot snapshot as date-keyed evidence in the same transaction;
old pilot receipts stay intact. UI distinguishes current window, latest
available completed day, missing days, retained evidence, bucket/ingest times,
last whole-run fetch, failure and renewal state. Broader Health stays unconnected.
No automation was created; native Site `automations` was empty on inspection.
